# ওয়েব কীভাবে কাজ করে?

আপনি ব্রাউজারে www.prothomalo.com লিখে Enter চাপলেন, আর কয়েক সেকেন্ডের মধ্যে পেজ চলে এল। এই কয়েক সেকেন্ডে পর্দার আড়ালে কী কী ঘটে, সেটাই ধাপে ধাপে দেখা যাক।
১. বড় ছবি: ক্লায়েন্ট ও সার্ভার

ওয়েবের মূল ধারণা খুব সহজ:

ক্লায়েন্ট হলো যে তথ্য চায়। আপনার ব্রাউজার (Chrome, Firefox) এই কাজ করে।
সার্ভার হলো যে তথ্য দেয়। এটা অন্য কোথাও থাকা একটা কম্পিউটার, যেটা সারাক্ষণ চালু থাকে।

উদাহরণ: রেস্টুরেন্টে আপনি খদ্দের (ক্লায়েন্ট), ওয়েটার হলো ইন্টারনেট, আর রান্নাঘর হলো সার্ভার। আপনি অর্ডার দেন, ওয়েটার রান্নাঘরে নিয়ে যায়, খাবার তৈরি হয়ে ফিরে আসে।

২. ইন্টারনেট আর ওয়েব এক জিনিস নয়
ইন্টারনেট হলো কম্পিউটারগুলোর বিশাল নেটওয়ার্ক, অর্থাৎ তার, ফাইবার, স্যাটেলাইট আর রাউটারের জাল। রাস্তাঘাটের মতো একটা অবকাঠামো।
ওয়েব (WWW) হলো ইন্টারনেটের ওপর চলা একটা সেবা, যেখানে ওয়েবসাইট ও ওয়েবপেজ থাকে। রাস্তার ওপর চলা গাড়ির মতো।

ইমেইল, অনলাইন গেম আর WhatsApp-ও ইন্টারনেট ব্যবহার করে, কিন্তু সেগুলো ওয়েবের অংশ নয়।

৩. Enter চাপার পর ধাপে ধাপে কী হয়
ধাপ ১: URL বিশ্লেষণ

https://www.prothomalo.com/bangladesh এই ঠিকানার তিনটি অংশ আছে:

অংশ মানে
https:// প্রোটোকল: কোন নিয়মে কথা হবে
www.prothomalo.com ডোমেইন: কোন সার্ভারের সাথে কথা হবে
/bangladesh পাথ: সার্ভারের ভেতরে কোন পেজ চাই
ধাপ ২: DNS লুকআপ (ঠিকানা খোঁজা)

কম্পিউটার নাম বোঝে না, বোঝে সংখ্যা। প্রতিটি সার্ভারের একটা IP address থাকে, যেমন 104.18.25.10।

DNS (Domain Name System) হলো ইন্টারনেটের ফোনবুক। আপনার ব্রাউজার জিজ্ঞেস করে, “prothomalo.com এর IP কত?” DNS উত্তর দেয়, “104.18.25.10।”

উদাহরণ: মোবাইলে আপনি "আম্মু" নামে সেভ করা নম্বরে ফোন দেন। ফোন নিজেই নামটা নম্বরে বদলে নেয়। DNS ঠিক এই কাজটাই করে।

ধাপ ৩: সংযোগ স্থাপন (TCP ও TLS)

IP পাওয়ার পর ব্রাউজার সার্ভারের সাথে সংযোগ তৈরি করে:

TCP হ্যান্ডশেক: দুই পক্ষ নিশ্চিত হয় যে তারা একে অপরকে শুনতে পাচ্ছে। যেন ফোনে "হ্যালো, শুনতে পাচ্ছেন?" "জি, শুনতে পাচ্ছি।"
TLS/SSL: https এর “s” এর মানে Secure। এখানে ডেটা এনক্রিপ্ট হয়, ফলে মাঝপথে কেউ আড়ি পাতলেও কিছু বুঝবে না। ব্রাউজারের ঠিকানার পাশে তালার চিহ্ন এটারই লক্ষণ।
ধাপ ৪: HTTP Request পাঠানো

ব্রাউজার সার্ভারকে একটা চিঠি লেখে:

GET /bangladesh HTTP/1.1
Host: www.prothomalo.com

এর মানে: "আমি /bangladesh পেজটা চাই।"

কয়েকটি গুরুত্বপূর্ণ HTTP মেথড:

মেথড কাজ উদাহরণ
GET তথ্য আনা নিউজ পেজ দেখা
POST নতুন তথ্য পাঠানো লগইন ফর্ম সাবমিট
PUT/PATCH তথ্য আপডেট করা প্রোফাইল এডিট
DELETE তথ্য মুছে ফেলা কমেন্ট ডিলিট
ধাপ ৫: সার্ভার প্রসেস করে

সার্ভারে একটা ওয়েব সার্ভার সফটওয়্যার (Nginx, Apache) থাকে, আর থাকে আপনার লেখা ব্যাকএন্ড কোড (Node.js, PHP, Python ইত্যাদি)। এটা:

রিকোয়েস্ট বোঝে
দরকার হলে ডেটাবেস থেকে তথ্য আনে (যেমন আজকের খবরের তালিকা)
পেজ তৈরি করে
ধাপ ৬: HTTP Response ফেরত আসে

সার্ভার উত্তর পাঠায়:

HTTP/1.1 200 OK
Content-Type: text/html

<html> ... পেজের কোড ... </html>

স্ট্যাটাস কোড দেখে বোঝা যায় কী হলো:

200: সব ঠিক আছে
301/302: পেজ অন্য জায়গায় সরে গেছে (redirect)
404: পেজ পাওয়া যায়নি
401/403: অনুমতি নেই
500: সার্ভারের ভেতরে সমস্যা
ধাপ ৭: ব্রাউজার পেজ আঁকে (Rendering)

সার্ভার থেকে আসে মূলত তিন ধরনের ফাইল, আর ব্রাউজার সেগুলো জোড়া লাগিয়ে পেজ বানায়:

ফাইল ভূমিকা বাড়ির উদাহরণ
HTML কাঠামো ও কনটেন্ট ইট-সিমেন্টের দেয়াল, ঘরের নকশা
CSS রং, ডিজাইন, লেআউট রং করা, সাজসজ্জা
JavaScript ইন্টারঅ্যাকশন ও লজিক বিদ্যুৎ, সুইচ, ফ্যান

HTML পড়ে ব্রাউজার একটা DOM Tree বানায়। এরপর CSS লাগায়, JavaScript চালায়, আর ছবি-ফন্ট ইত্যাদির জন্য আরও রিকোয়েস্ট পাঠায়। একটা পেজ লোড হতে অনেক সময় ডজন ডজন রিকোয়েস্ট যায়।

৪. পুরো প্রবাহ এক নজরে
আপনি URL লিখলেন
↓
DNS: নাম → IP address
↓
TCP + TLS: নিরাপদ সংযোগ
↓
HTTP Request (GET /page)
↓
সার্ভার: কোড চালায় + ডেটাবেস থেকে ডেটা আনে
↓
HTTP Response (HTML, CSS, JS)
↓
ব্রাউজার রেন্ডার করে → পেজ দেখা যায়
৫. একটা বাস্তব উদাহরণ: অনলাইনে লগইন

ধরুন কোনো ওয়েবসাইটে ইমেইল ও পাসওয়ার্ড দিয়ে লগইন করছেন:

আপনি ফর্ম পূরণ করে “Login” চাপলেন।
ব্রাউজার POST রিকোয়েস্ট পাঠাল, সাথে আপনার ইমেইল-পাসওয়ার্ড (HTTPS দিয়ে এনক্রিপ্টেড)।
সার্ভারের ব্যাকএন্ড কোড ডেটাবেসে খুঁজে দেখল, এই ইমেইল-পাসওয়ার্ড মিলছে কি না।
মিললে সার্ভার একটা সেশন/টোকেন তৈরি করে Cookie আকারে আপনার ব্রাউজারে পাঠাল।
পরের প্রতিটি রিকোয়েস্টে ব্রাউজার ওই কুকি সাথে পাঠায়, তাই সার্ভার বোঝে "এটা সেই লগইন করা রহিম।"

কারণ HTTP নিজে কিছু মনে রাখে না (stateless)। কুকি আর সেশন সেই মনে রাখার কাজটা করে।

৬. ফ্রন্টএন্ড, ব্যাকএন্ড ও ডেটাবেস

এই কাঠামোটা বুঝলে ফুল স্ট্যাক ডেভেলপমেন্টের পুরো ছবিটা পরিষ্কার হয়:

স্তর কাজ সাধারণ টুল
Frontend ব্যবহারকারী যা দেখে ও ব্যবহার করে HTML, CSS, JavaScript, React
Backend লজিক, নিরাপত্তা, API Node.js, Express, Django, Laravel
Database ডেটা জমা রাখা MySQL, PostgreSQL, MongoDB

ফ্রন্টএন্ড অনেক সময় API এর মাধ্যমে ব্যাকএন্ডের সাথে কথা বলে। API সাধারণত JSON ফরম্যাটে ডেটা আদান-প্রদান করে:

json
{
"name": "রহিম",
"role": "developer"
}
৭. ওয়েবসাইট ইন্টারনেটে কীভাবে থাকে
Hosting: আপনার ওয়েবসাইটের ফাইল কোনো সার্ভারে রাখা হয় (AWS, DigitalOcean, Vercel ইত্যাদি), যেটা ২৪ ঘণ্টা চালু থাকে।
Domain: ঠিকানা কিনতে হয় (যেমন myshop.com), আর DNS-এ সেটা সার্ভারের IP-র সাথে জুড়ে দিতে হয়।
CDN: একই ফাইল পৃথিবীর বিভিন্ন জায়গায় কপি করে রাখা হয়, যাতে ঢাকার ব্যবহারকারী ঢাকার কাছের সার্ভার থেকেই দ্রুত ডেটা পায়।
সংক্ষেপে মনে রাখার সূত্র

URL → DNS → সংযোগ → Request → সার্ভার প্রসেস → Response → ব্রাউজার রেন্ডার

এই প্রবাহটা পরিষ্কার বুঝে গেলে ডেভেলপার হিসেবে যেকোনো বাগ ধরা সহজ হয়। যেমন সমস্যাটা DNS-এ, নেটওয়ার্কে, ব্যাকএন্ডে নাকি ফ্রন্টএন্ডে, তা বোঝা যায়। ব্রাউজারের DevTools → Network ট্যাবে (F12 চাপুন) গিয়ে যেকোনো সাইট খুলে নিজের চোখেই এই রিকোয়েস্ট-রেসপন্সগুলো দেখে নিতে পারেন।

চাইলে পরের ধাপে HTTP/HTTPS, কুকি-সেশন-JWT, বা REST API নিয়ে আরও গভীরে যেতে পারি।
